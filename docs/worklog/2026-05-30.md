## KRDS Service Design Polish

### Goal

Move beyond color neutralization and bring the existing admin and iframe UI closer to service-ready KRDS-like visual quality without changing product behavior.

### Research Notes

- KRDS guidance emphasizes inclusive UI/UX, consistent service standards, reusable components, and design tokens.
- KRDS design principles allow each service to optimize for its own context while keeping a shared, consistent experience.
- USWDS token guidance supports limiting visual decisions to tokenized color, spacing, typography, and surface values.

## Design D0 Blog Compatibility Audit

### Goal

Audit the current iframe widget against representative blog contexts before making more design changes.

### Work Log

- Confirmed `docs/todos/design-d0-blog-compatibility-audit.md` existed before starting.
- Created temporary `design-d0-*` QA data and deleted it after the audit.
- Tested six simulated blog contexts:
  - Minimal white article.
  - Off-white editorial article.
  - Dense text-heavy article.
  - Image-heavy magazine article.
  - Dark article.
  - Narrow mobile article.
- Confirmed no application code changes were made during D0.

### Findings

- No horizontal overflow was found in any simulated blog context.
- Public iframe body background remained transparent.
- The dominant compatibility issue was vertical footprint, not color.
- The copied iframe height was `720px`.
- Desktop iframe-height-to-article-width ratios ranged from `0.86` to `1.06`.
- Narrow mobile ratio was `1.99`, which is too dominant for an article body.
- Panel shadow, title band, and question block were acceptable but could be quieter.

### Decision

Proceed to D1 embed footprint reduction.
