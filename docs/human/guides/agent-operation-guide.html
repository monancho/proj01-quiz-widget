Agent Operation Guide

Codex 작업 규칙을 사람이 확인하기 쉽게 정리한 중간 점검용 문서입니다.

Project: proj01-quiz-widget Updated: 2026-05-29 Human checkpoint document

핵심 요약

AGENTS.md는 AI가 매 세션 참고하는 고정 지도입니다.

docs/00-project-status.md와 docs/worklog/는 계속 바뀌는 상태 기록입니다.

이 HTML 문서는 사람이 확인해야 할 때 보는 보고서이며, 매번 자동으로 만들거나 갱신할 필요는 없습니다.

문서 역할 분리

문서 대상 역할 갱신 시점
AGENTS.md AI / Codex 매 세션 따라야 할 고정 작업 규칙 운영 방식이 바뀔 때만
docs/00-project-status.md 사람 + AI 현재 브랜치, Phase, 완료/다음 작업 상태판 작업 상태가 바뀔 때
docs/worklog/YYYY-MM-DD.md 사람 + AI 날짜별 작업 로그와 검증 기록 의미 있는 작업 진행 중
docs/human/index.html, guides/, reports/, decisions/ 사람 사람용 문서 입구, 운영 안내, 중간 보고, 의사결정 기록 요청 또는 마일스톤 때만
docs/03-task-breakdown.md 사람 + AI 전체 Phase 기준 작업 목록 계획이 바뀔 때

새 세션 시작 순서

AI가 먼저 읽을 것
  1. AGENTS.md
  2. docs/00-project-status.md
  3. 최신 docs/worklog/YYYY-MM-DD.md
  4. docs/03-task-breakdown.md
사람이 확인할 것
  • 현재 Phase가 무엇인지
  • 최근 커밋과 검증 결과
  • 다음 작업이 명세와 맞는지
  • 체크포인트 보고가 필요한지

고정 운영 규칙

  • develop에서 기능 브랜치를 만들어 작업합니다.
  • docs/03-task-breakdown.md의 Phase 순서를 따릅니다.
  • 작업 상태가 바뀌면 docs/00-project-status.md를 갱신합니다.
  • 의미 있는 작업 진행은 최신 worklog에 기록합니다.
  • 사람용 HTML 문서는 매번 만들지 않고, 중간 보고나 체크포인트에만 갱신합니다.
  • 검증 없이 커밋하지 않습니다.

현재 브랜치 전략

브랜치 역할
develop 통합 브랜치
feature/project-scaffold Phase 0 + Phase 1
feature/server-api-mvp Phase 2 + Phase 3 + Phase 4
feature/client-embed-mvp Phase 5
feature/admin-mvp Phase 6

Codex에게 줄 시작 문장

새 세션에서 이어서 작업할 때는 아래 문장을 사용하면 됩니다.

AGENTS.md를 먼저 읽고,
docs/00-project-status.md와 최신 worklog를 확인한 뒤,
현재 작업 상태를 요약하고 다음 Phase부터 이어서 진행해줘.
